Siga estas diretrizes para configurar um ambiente de desenvolvimento para o freeCodeCamp. Isso é altamente recomendado se você deseja contribuir regularmente.

<À parte type='danger' title='Aviso para usuários do Windows'>

- Você não pode compilar e executar a base de código no Windows; você [precisará usar o WSL2](/how-to-setup-wsl/) e, em seguida, seguir o restante das instruções para Linux ou macOS.
- Você não pode usar o Prompt de Comando do Windows, Git Bash ou PowerShell.

- Os requisitos de hardware precisam ser melhores do que [o que recomendamos](/how-to-setup-freecodecamp-locally/#how-to-prepare-your-local-machine) para acomodar uma configuração baseada em WSL.

</Aside>

## Faça um fork do repositório do freeCodeCamp no GitHub

Você precisará fazer um fork do repositório do freeCodeCamp no GitHub para obter sua própria cópia da base de código. Isso permitirá que você siga um fluxo de trabalho baseado em Git para contribuir com o freeCodeCamp.

**Siga estas etapas para fazer um fork do repositório:**

<Etapas>

1. Clique no botão abaixo para fazer um fork do repositório do freeCodeCamp no GitHub.

<LinkButton
href='https://github.com/freeCodeCamp/freeCodeCamp/fork'
icon='seti:github'
iconPlacement='start'
variant='secondary'
target='_blank'
>
Fork do freeCodeCamp
</LinkButton>

2. Na página de criação de um novo fork, verifique os detalhes e clique no botão **Criar fork**.

3. Você será redirecionado automaticamente para o seu fork, a URL deve ser algo como `https://github.com/SEU_NOME_DE_USUÁRIO/freeCodeCamp`.

</Steps>

Pronto! Você bifurcou o repositório do freeCodeCamp com sucesso. Você sempre pode excluir seu fork se quiser começar do zero.

<Aside type='tip' title='Você sabia?'>

O repositório principal em `https://github.com/freeCodeCamp/freeCodeCamp` é frequentemente chamado de repositório `upstream`. Seu fork em `https://github.com/YOUR_USER_NAME/freeCodeCamp` é frequentemente chamado de repositório `origin`.

</Aside>

## IDE na nuvem ou sua própria máquina?

Em seguida, você precisa escolher entre configurar um IDE na nuvem ou sua própria máquina.

Se você deseja fazer uma contribuição única, use o Gitpod, o GitHub Codespaces ou outro IDE baseado em nuvem para fazer alterações. O Gitpod configura um ambiente pronto para codificação em apenas alguns minutos no seu navegador. Para contribuições de longo prazo, recomendamos configurar o freeCodeCamp em sua máquina local.

#### IDE em nuvem (Gitpod, CodeSpaces, etc.) <Badge text="Recommended" variant="tip" size="small" />

**Prós:**

- Sem requisitos mínimos de hardware.
- Não é necessário instalar nenhum software.
- Repositório sempre atualizado.
- Fácil de configurar, você só precisa de um navegador — incluindo navegadores mobile.

**Contras:**

- Requer conexão com a internet para funcionar.
- Uso gratuito limitado — aproximadamente 50 horas.

#### Sua própria máquina (configuração local)

**Prós:**

- Mais rápido para fazer alterações e visualizá-las em tempo real (dependendo da capacidade da máquina).
- Conexão mínima com a internet necessária após a configuração.

**Contras:**

- Requisitos mínimos de hardware robustos.
- Software adicional necessário.
- Maior tempo de download e configuração.

### Como preparar um IDE na nuvem

<Aside type='note'>

Pule para [como preparar sua máquina local](#como-preparar-sua-máquina-local) se não tiver interesse em usar um IDE na nuvem.

</Aside>

#### Gitpod

Automatizamos o processo de instalação de todas as dependências e ferramentas necessárias. Com o Gitpod, você obtém um ambiente gratuito pronto para programar em poucos minutos, útil se você não tiver acesso a um computador ou quiser fazer alterações pontuais.

**Existem várias maneiras de iniciar um ambiente de trabalho no Gitpod:**

<Passos>

1. Adicione `gitpod.io/#` antes de qualquer URL do GitHub.

Visite seu fork em `https://github.com/SEU_NOME_DE_USUÁRIO/freeCodeCamp.git`, adicione `gitpod.io/#` antes da URL na barra de endereços e pressione Enter.

Resumindo, acesse

```
gitpod.io/#https://github.com/SEU_NOME_DE_USUÁRIO/freeCodeCamp.git
```

e você deverá ver um espaço de trabalho criado para você. Isso funciona para qualquer repositório ou pull-request no GitHub.

2. Como alternativa, instale uma das extensões abaixo para o seu navegador.
- [Chrome Webstore](https://chrome.google.com/webstore/detail/gitpod-always-ready-to-co/dodmmooeoklaejobgleioelladacbeki) - funciona com navegadores baseados em Chromium, como Google Chrome, Brave, Edge, etc.
- [Complemento do Firefox](https://addons.mozilla.org/en-US/firefox/addon/gitpod) - Firefox

Após a instalação, você verá um botão "Gitpod" em cada repositório, solicitação de pull, etc., como um atalho prático para iniciar um espaço de trabalho a partir daí. Consulte a página da extensão para obter detalhes, capturas de tela, etc.

</Steps>

<Aside type='note' title='GitPod está pronto!'>

Pronto! Agora você pode pular para a seção [sincronizando a partir do pai](#set-up-syncing-from-parent) depois de iniciar um espaço de trabalho do Gitpod.

A maior parte deste guia se aplica aos espaços de trabalho do Gitpod. Certifique-se de verificar a [seção de solução de problemas](/troubleshooting-development-issues/) para quaisquer problemas.

</Aside>

### Como preparar sua máquina local

<Aside type='note'>

Pule para [como preparar uma IDE em nuvem](#como-preparar-uma-IDE-em-nuvem) se não estiver interessado em configurar uma máquina local.

</Aside>

<Card title='Requisitos do Sistema' icon='laptop'>

Aqui estão os requisitos mínimos de sistema para executar o freeCodeCamp localmente:

- Uma CPU rápida (4 ou mais núcleos)
- Pelo menos 8 GB de RAM
- macOS, Linux ou Windows 10 ou 11 ([com WSL](/how-to-setup-wsl/))
- 8 a 10 GB de espaço livre em disco
- (Opcional) Conexão de internet de 30 a 50 Mbps

</Card>

Oferecemos suporte principalmente ao desenvolvimento em sistemas Linux e Unix, como Ubuntu e macOS. Você pode desenvolver no Windows 10 ou 11 apenas com WSL2. Você pode seguir [este guia](/how-to-setup-wsl/) para configurar o WSL2. Não é possível usar Prompt de Comando, Git Bash ou PowerShell para executar o freeCodeCamp nativamente no Windows.

Comece instalando o software necessário para o seu sistema operacional.

#### Pré-requisitos:

| Pré-requisito | Versão | Observações |
| --------------------------------------------------------------------------------------------- | ------- | ------------------------------------------------------------------------------------------- |
| [Node.js](http://nodejs.org) | `22.x` | Usamos a versão "LTS Ativa", consulte [Cronograma LTS](https://nodejs.org/en/about/releases/). |
| [pnpm](https://pnpm.io/installation) | `10.x` | - |
| [MongoDB Community Server](https://docs.mongodb.com/manual/administration/install-community/) | `8.0.x` | - |
| [Docker Compose](https://docs.docker.com/compose/install/) | `2.x` | - |

<Aside type='caution' title='Você verificou a versão?'>

Se você tiver uma versão diferente de um software necessário, instale a versão recomendada. Consulte a [seção de solução de problemas](/troubleshooting-development-issues/) para obter mais detalhes.

</Aside>

**Execute os seguintes comandos para validar as versões:**

```bash
node -v
```

```bash
pnpm -v
```

Depois de instalar os pré-requisitos, você precisa preparar seu ambiente de desenvolvimento. Isso é comum para muitos fluxos de trabalho de desenvolvimento e você só precisará fazer isso uma vez.

#### Pré-requisitos adicionais:

<Etapas>

1. Instale o [Git](https://git-scm.com/) ou seu cliente Git favorito, caso ainda não tenha feito isso. Atualize para a versão mais recente; a versão que veio com o seu sistema operacional pode estar desatualizada.

2. (Opcional, mas recomendado) [Configure uma chave SSH](https://help.github.com/articles/generating-an-ssh-key/) para o GitHub.

3. Instale um editor de código de sua escolha. Se não tiver certeza de qual usar, recomendamos o [Visual Studio Code](https://code.visualstudio.com/) — é gratuito e de código aberto.

4. Configure o linting para o seu editor de código.

Você deve ter o [ESLint em execução no seu editor](http://eslint.org/docs/user-guide/integrations.html), e ele destacará qualquer coisa que não esteja em conformidade com o [Guia de Estilo JavaScript do freeCodeCamp](http://forum.freecodecamp.org/t/free-code-camp-javascript-style-guide/19121).

<Aside type='tip' title='Preste Atenção aos Erros'>

Não ignore nenhum erro de linting. Eles têm como objetivo **ajudar** você e garantir uma base de código limpa e simples.

</Aside>

</Steps>

## Clone seu Fork do GitHub

Você já deve ter um fork do freeCodeCamp no GitHub. Caso contrário, [siga estas instruções para fazer o fork do repositório](/how-to-setup-freecodecamp-locally/#fork-the-freecodecamp-repository-on-github). Em seguida, você precisará [clonar](https://help.github.com/articles/cloning-a-repository/) seu fork para sua máquina local.

**Execute estes comandos em sua máquina local:**

<Steps>

1. Abra um terminal no diretório dos seus projetos, por exemplo:

```
/home/username/projects/
```

2. Clone seu fork do freeCodeCamp, substituindo `SEU_NOME_DE_USUÁRIO` pelo seu nome de usuário do GitHub

```bash
git clone --depth=1 https://github.com/SEU_NOME_DE_USUÁRIO/freeCodeCamp.git
```

Isso fará o download de todo o repositório do freeCodeCamp para o seu diretório de projetos.

<Aside type='note'>
`--depth=1` cria um clone superficial do seu fork, com arquivos do histórico/commit
mais recente.
</Aside>

3. **(Opcional)** As versões localizadas do nosso currículo estão armazenadas no [repositório i18n-curriculum.](https://github.com/freeCodeCamp/i18n-curriculum) Se você pretende executar uma versão localizada do currículo, siga os próximos passos ou pule para a próxima seção.

**Clone o submódulo i18n-curriculum:**

```bash
cd freeCodeCamp
```

```bash
git submodule update --init
```

</Steps>

## Configurando a Sincronização do Repositório Principal

Agora que você baixou uma cópia do seu fork, precisará configurar um repositório `upstream` remoto para o repositório principal.

[Como mencionado anteriormente](#fork-the-freecodecamp-repository-on-github), o repositório principal é chamado de repositório `upstream`. Seu fork é chamado de repositório `origin`.

Você precisa de uma referência do seu clone local para o repositório `upstream`, além do repositório `origin`. Isso permite que você sincronize as alterações do repositório principal sem a necessidade de bifurcar e clonar repetidamente.

<Passos>

1. Altere o diretório para o novo diretório do freeCodeCamp, caso ainda não esteja lá:

```bash
cd freeCodeCamp
```

2. Adicione uma referência remota ao repositório principal do freeCodeCamp:

```bash
git remote add upstream https://github.com/freeCodeCamp/freeCodeCamp.git
```

3. Certifique-se de que a configuração esteja correta:

```bash
git remote -v
```

A saída deve ser semelhante à mostrada abaixo (substituindo `SEU_NOME_DE_USUÁRIO` pelo seu nome de usuário do GitHub):

```
origin https://github.com/SEU_NOME_DE_USUÁRIO/freeCodeCamp.git (buscar)
origin https://github.com/SEU_NOME_DE_USUÁRIO/freeCodeCamp.git (push)
upstream https://github.com/freeCodeCamp/freeCodeCamp.git (buscar)
upstream https://github.com/freeCodeCamp/freeCodeCamp.git (push)
```

</Steps>

## Executando o freeCodeCamp Localmente

Agora que você possui uma cópia local do freeCodeCamp, siga estas instruções para executá-lo localmente. Isso permitirá que você:

- Visualize as edições nas páginas como elas apareceriam na plataforma de aprendizagem.
- Trabalhe em problemas e melhorias relacionados à interface do usuário.
- Depure e corrija problemas com os servidores de aplicativos e aplicativos clientes.

### Etapa 1: Configurar o Arquivo de Variáveis ​​de Ambiente

As chaves de API padrão e as variáveis ​​de ambiente são armazenadas no arquivo `sample.env`. Este arquivo precisa ser copiado para um novo arquivo chamado `.env`, que é acessado dinamicamente durante a etapa de instalação.

```bash
cp sample.env .env
```

As chaves no arquivo `.env` _não_ precisam ser alteradas para executar o aplicativo localmente. Você pode deixar os valores padrão copiados de `sample.env` como estão.

<Aside type='note'>

Lembre-se de que, se quiser usar serviços como Auth0 ou Algolia, você precisará adquirir suas próprias chaves de API para esses serviços e editar as entradas adequadamente no arquivo `.env`.

</Aside>

### Etapa 2: Instalar Dependências e Configuração Compartilhada

Instale as dependências e defina a configuração compartilhada para os serviços.

``bash
pnpm install
```

```bash
pnpm run create:shared
```

### Etapa 3: Inicie o MongoDB e crie o banco de dados

Antes de executar o aplicativo localmente, você precisará iniciar um servidor MongoDB como um conjunto de réplicas.

<Etapas>

1. Pare qualquer servidor MongoDB existente que use a porta 27017 (se você já tiver um conjunto de réplicas em execução nessa porta, pode pular esta e a próxima etapa)

1. Inicie o servidor MongoDB como um conjunto de réplicas:

```bash
docker compose --file ./api/tools/docker-compose.yml up -d
```

1. Crie o banco de dados e configure um novo usuário:

<Aside type='note' title='MongoDB URI'>

O padrão deve ser adequado para a maioria dos usuários. Se estiver usando uma configuração personalizada, modifique o `MONGOHQ_URL` no arquivo `.env` conforme necessário.

</Aside>

```bash
pnpm run seed
```

Isso configurará um novo usuário sem nenhuma certificação concluída, entre outras coisas. Geralmente, isso é mais do que suficiente para você começar.

1. **(Opcional)** Configure um usuário com certificações concluídas:

```bash
pnpm run seed:certified-user
```

Isso é útil para depuração avançada ou criação de testes para a plataforma.

<Aside type='caution' title='Limpar os cookies'>

Você terá que limpar os cookies do seu navegador e fazer login novamente após a propagação do usuário certificado.

</Aside>

</Steps>

<Card title='Notas sobre o Banco de Dados' icon='seti:db'>
<Aside type='tip' title='Instalar o MongoDB como um serviço em segundo plano'>
Você pode evitar ter que iniciar o MongoDB toda vez instalando-o como um
serviço em segundo plano. Você pode [saber mais sobre isso na documentação
do seu sistema operacional](https://docs.mongodb.com/manual/administration/install-community/).
</Aside>
</Card>

### Etapa 4: Iniciar o Aplicativo Cliente e o Servidor de API

Agora você pode iniciar o servidor de API e os aplicativos clientes.

```bash
pnpm run develop

```

Quando estiver pronto, abra um navegador e visite: `http://localhost:8000`

<LinkButton
href='http://localhost:8000'
icon='external'
variant='secondary'
target='_blank'
>
`http://localhost:8000`
</LinkButton>

<Aside type='tip' title="Parabéns - você está pronto!">

Se o aplicativo carregar, faça login. Agora você tem uma cópia completa da plataforma de aprendizagem do freeCodeCamp em execução na sua máquina local. Vá em frente e comece a fazer alterações na base de código.

</Aside>

**Algumas observações:**

- O servidor de API atende endpoints em `http://localhost:3000`.
- O aplicativo Gatsby atende o aplicativo cliente em `http://localhost:8000`.
- Todas as APIs estão disponíveis em `http://localhost:3000/explorer`.

<Aside type='note'>

Se tiver problemas com a configuração, consulte a [seção de solução de problemas](/troubleshooting-development-issues/).

</Aside>

## Referência de Comandos Rápidos

<Card title='Scripts Úteis para usar localmente' icon='open-book'>

| Comando | Descrição |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------- |
| `pnpm install` | Instala/reinstala todas as dependências e inicializa os diferentes serviços. |
| `pnpm run seed` | Cria usuários de teste autorizados e os insere no MongoDB. Também executa `seed:exams` e `seed:surveys` abaixo. |
| `pnpm run seed:certified-user` | Cria usuários de teste autorizados com certificações totalmente concluídas e os insere no MongoDB. |
| `pnpm run seed:exams` | Cria exames e os insere no MongoDB. |
| `pnpm run seed:surveys` | Cria pesquisas para usuários padrão e os insere no MongoDB. |
| `pnpm run develop` | Inicia os aplicativos cliente e servidor da API do freeCodeCamp. |
| `pnpm run clean` | Desinstala todas as dependências e limpa os caches. |

</Card>
